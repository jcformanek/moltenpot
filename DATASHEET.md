# Datasheet — Molten Pot

This datasheet follows the *Datasheets for Datasets* framework (Gebru et al.,
2021) and documents the offline-RL datasets released with the Molten Pot
benchmark. The datasets are hosted on the Hugging Face Hub at
[`jcformanek/moltenpot`](https://huggingface.co/datasets/jcformanek/moltenpot)
and are auto-downloaded on first use by the training scripts in this
repository.

---

## Motivation

**For what purpose was the dataset created?**
To enable reproducible research on *offline* reinforcement learning in
*mixed-motive* (social-dilemma) multi-agent settings. Existing offline-RL
benchmarks are overwhelmingly single-agent or fully cooperative; Molten Pot
provides logged trajectories on substrates where agents' incentives are
partially aligned and partially in conflict, across three evaluation settings
(single-scenario, multi-scenario with the scenario label withheld, and
zero-shot social generalisation across held-out scenario splits).

**Who created the dataset and on behalf of whom?**
The authors of the accompanying paper.

---

## Composition

**What do the instances represent?**
Each instance is a recorded **episode** of a focal-agent population acting in a
MeltingPot scenario, stored from every focal agent's egocentric perspective.

**Scale.**

| Quantity | Value |
|---|---|
| Substrates | 5 (Coins, Coop Mining, Clean Up, Commons Harvest, Allelopathic Harvest) |
| Scenarios | 47 |
| Episodes | ~47,000 |
| Episode horizon | 1,000 timesteps |
| Focal-agent trajectories | ~186,000 |
| Focal-agent transitions | ~185 million |
| Total size on disk | ~1 TB |

**What data does each instance consist of?**
Per episode, per focal agent, stored in HDF5 (`<substrate>/<scenario>/dataset.hdf5`):

- `obs` — `(T, A, 3, 88, 88)` `uint8` RGB egocentric frames (LZF-compressed),
- `actions` — `(T, A)` `int32` discrete actions,
- `rewards` — `(T, A)` `float32`,
- `dones` — `(T,)` `bool`,
- `h_states` — `(T+1, A, H)` `float32` recurrent hidden states from the
  behaviour policy at collection time.

`T` is the episode length, `A` the number of focal agents in the scenario
(1–14), `H` the GRU hidden size.

**Are there labels?**
The scenario identity is known for each file. In *Setting 2* the scenario label
is deliberately withheld from the learner at training time; *Setting 3* defines
disjoint train/test scenario splits for zero-shot evaluation (see
`configs/experiment/benchmark_*.yaml`).

**Does the dataset contain confidential or personal data?**
No. All trajectories are generated entirely in simulation; there is no human,
personal, or otherwise sensitive data.

---

## Collection process

**How was the data collected?**
Trajectories were generated by training independent PPO behaviour policies on
each scenario (the `scripts/train_ppo.py` pipeline) and **logging episodes
uniformly across the entire course of training** — from random initialisation
through to the converged policy. Each scenario's dataset is therefore a
skill-mixed cross-section rather than only expert demonstrations, which is the
regime offline-RL methods are meant to handle.

**Over what timeframe / with what sampling strategy?**
Episodes are sampled at uniform training-step intervals (one recorded episode
every `total_steps / target_episodes` steps), so the return distribution within
each scenario spans the full learning curve. Per-scenario return distributions
are visualised on the companion site.

**Software used.** The data-collection and training code is in this repository;
the environments are DeepMind MeltingPot substrates and scenarios.

---

## Preprocessing / cleaning / labelling

Observations are stored as `uint8` (0–255) for space efficiency and normalised
to `[0, 1]` float at load time by the dataset classes in
`moltenpot/data_utils.py`. No other transformation is applied; raw logged
trajectories are preserved. The HDF5 layout and the streaming `Dataset` classes
are documented in `moltenpot/data_utils.py`.

## Uses

**What is the dataset intended to be used for?**
Training and evaluating offline-RL algorithms (this repo ships BC, BCQ, IQL, and
CQL) under the three settings above, and studying social outcomes (per-agent
return inequality / Gini, background-agent welfare, generalisation gap — see
`moltenpot/algorithms/eval_utils.py`).

**What (potentially) inappropriate uses are there?**
The datasets describe behaviour in abstract grid-world social dilemmas and
should not be treated as models of real human social behaviour or used to make
claims about specific human populations.
